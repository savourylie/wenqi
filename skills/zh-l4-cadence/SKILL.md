# zh-l4-cadence：第四層單層正交技能（篇章呼吸與音律節奏）

專注處理中文「大樹長句憋氣、代詞累贅、存在句空轉與句尾拖沓」的第四層西化病灶：依中文「竹節流水句」原則將過長分句切入 7～15 字呼吸舒適區；順應中文「話題優先（Topic-prominent）」特性提取主語代詞公因式（零形回指 Zero Anaphora）並刪去無生命「它們」；坍縮「有…存在」「基於這個原因」與空泛的「是…的」；並以精煉四字格與強動詞收束段落結尾。

## 觸發時機

- 使用者直接呼叫 `/zh-l4-cadence`（或 `$zh-l4-cadence`）針對檔案或對話貼文進行 L4 單層診斷與雙版本 Diff 改寫。
- 作者希望在不受 L1（弱動詞／名物化／偽術語／被動）、L2（左分支與的字連環套）、L3（介詞外框與雙重因果）干擾的情況下，單獨觀察並驗收「L4 篇章呼吸與音律節奏」規則的獨立效果。

## 共用執行環境與 L5 預檢握手規範

### 步驟 0：解析引擎路徑與 Python 直譯器

在呼叫掃描器前先定位 `WENQI_ROOT` 與 `WENQI_PYTHON`（於任一工作目錄執行絕對路徑的 `ast_scanner.py` 皆可正常偵測目標檔案所屬的 Git Repo）：

1. **`WENQI_ROOT` 解析順序**（取第一個包含 `engine/ast_scanner.py` 的路徑）：
   - 本 `SKILL.md` 所在位置往上兩層（即 `skills/<skill-name>/SKILL.md` 對應的專案根目錄）。
   - 目前工作目錄。
   - 環境變數 `$WENQI_ROOT`。
   - 若以上皆找不到，先向使用者詢問 `wenqi` 安裝路徑再繼續。
2. **`WENQI_PYTHON` 解析順序**：
   - 若 `"$WENQI_ROOT/.venv/bin/python"` 存在，優先使用它（避免系統 `python3` 缺少 `jieba` 依賴）。
   - 否則使用 `python3`（若已在 `WENQI_ROOT` 內且啟用含 `jieba` 的環境，即等同 `python3 engine/ast_scanner.py ...`）。
3. **輸出解析提醒**：`ast_scanner.py` 的 `stdout` 為純 JSON，`jieba` 詞典載入訊息走 `stderr`。執行與解析時只讀取 `stdout`，切勿將 `stderr` 混入 JSON 解析。

### 步驟 1：L5 守門員前置檢查與握手銜接（L5-First 原則）

依專案規範，執行任何單層掃描前必須確保同一份輸入已完成 L5 預檢定調，避免未登錄領域專有名詞遭誤傷：

1. **同對話已完成 L5 握手**：若同對話已對相同 `target_id` 與 `content_hash` 執行過 `zh-l5-guard`（或已完成 `preflight` 確認），直接讀取「L5 守門員握手摘要」中的 `--profile <tech|social|essay>`（以及必要時的 `--ephemeral-whitelist "<詞1,詞2>"`），帶入下一步的 `--mode lint` 指令。
2. **同對話尚未完成 L5 握手**：先對同一份輸入執行 `--mode preflight`（檔案模式帶 `--file "<target_path>"`，貼文模式帶 `--stdin`）：
   - 若 `suspect_terms_for_review` 非空，或屬於本對話首次處理該稿件且作者尚未明示語體，先依 `zh-l5-guard` 規範發起單輪互動確認語體（`tech` / `social` / `essay`）與疑似詞作用域（`[G]` / `[L]` / `[X]`），並完成 `--mode update-state` 或記錄 `--ephemeral-whitelist` 後，再進入本層 `--mode lint`。
   - 若 `suspect_terms_for_review` 為空且作者已明示語體，直接帶入該 `--profile` 執行本層 `--mode lint`。

## 核心鐵律與最小手術防呆（Guardrails）

### 1. 嚴格正交隔離約束（Strict Orthogonality Guardrail）

- **只改本層 `issues` 標記的 `span`**：Agent 只能修改本次 `--mode lint --layer <L1|L2|L3|L4>` 回傳之 `issues` 陣列所標記的原文 `span` 及其直接語法依存部位。
- **同句其他層級病灶絕對禁止修改**：即使 `target_sentence` 同時存在其他層級的病灶（例如跑 `zh-l2-branching` 時句中有 L1 的弱動詞「進行了」、跑 `zh-l1-vitality` 時句首有 L3 的介詞外框「在…的過程當中」、跑 `zh-l3-logic` 時句中有 L4 的重複代詞「他的」，或單層掃描下未列入本層 `issues` 的 L0 補語用字錯字如「跑的很快」），**在【版本 A】與【版本 B】中皆絕對禁止修改未標記在本層 `issues` 的部位**。這能確保作者精確觀察單一層級規則的獨立效果，絕不與 `wenqi-all` 的全層折疊重構混淆。

### 2. 最小手術防呆（Minimal-Surgery Guardrails）

1. **禁止替換必留實詞（`must_keep_content_words`）**：
   - 嚴格禁止替換、刪減或改寫該句 diagnostic payload 中 `must_keep_content_words` 列出的所有作者原詞。
   - 若某個可替換詞在同句其他位置仍須保留，Scanner 會自動將該 issue 的 `instruction` 覆寫為「`保留…的原字，可調整…的語序`」；此時【版本 A】與【版本 B】皆必須保留該原字。
2. **禁止拆改凍結專有名詞（`frozen_whitelist_hits`）**：
   - 凡列於 `frozen_whitelist_hits` 的白名單保護詞（如 `高可用性`、`冪等性`、`局部性`、`進行 Fine-tuning` 等），在【版本 A】與【版本 B】中皆須原字完整保留，絕對禁止拆解、翻譯或換詞。
3. **禁止 AI 腔增飾（Zero AI Embellishments）**：
   - 禁止無中生有添加原文沒有的形容詞、副詞、成語、連接詞、情緒鋪陳或總結尾句；只針對本層 `issues` 執行減法與結構還原。
4. **零命中空狀態（Zero-Issue Handling）**：
   - 若 `--mode lint` 回傳 `summary.flagged_sentences == 0`（`diagnostics: []`），直接向作者回報「本層未檢出病灶，原文無須修改」，不得輸出空白 Diff 或自行挑刺改寫。

## 雙版本 Diff 輸出規範與作者裁決權（§6.4）

### 1. 雙版本 Diff 固定輸出格式

針對 `diagnostics` 陣列中的每一筆句級診斷，固定以下列 Markdown 結構輸出（不得省略任何欄位）：

```markdown
### 📍 Line <line_number> (`<sentence_id>`)
- **命中規則**：`[<rule_id>]` <病灶名稱>（若該 issue 含 `"severity": "info"` 則標註 `[<rule_id> (info)]`；同句多條本層規則時以頓號並列）
- **理論依據**：<直接引用或彙整該句本層 issues 的 `theoretical_basis`>
- **保護錨點**：🔒 凍結專有名詞：`<frozen_whitelist_hits 以頓號並列，空陣列則填「無」>` | ⚓ 必留實詞：`<must_keep_content_words 以頓號逐一列出>`

**【原句】**
> <target_sentence 原文，將本層 issues 命中的 span 以 **粗體** 標示>

**【版本 A：微調版 (Conservative — 僅針對本層 span 最小字面微調，保留原句結構與他層原字)】**
> <僅對本層命中 span 依 instruction 執行最低限度字面替換／刪減／斷句；同句他層病灶 100% 原字保留>

**【版本 B：竹節重構版 (Idiomatic — 在本層職責內強化動詞張力／後飾展開／竹節節奏，仍嚴格保留他層原字)】**
> <在本層命中 span 及其直接依存範圍內做更道地的語法或韻律重構；同句他層病灶同樣 100% 原字保留>
```

### 2. 版本 A 與版本 B 的單層改寫邊界及特殊診斷處置

- **單層正交下的 A/B 差異邊界**：
  - **【版本 A：微調版】**：嚴格對準本層 `issues` 的 `span` 做最小字面手術（直接依 `instruction` 拔除本層贅字、還原動詞或補上逗號，不調整分句其餘語序）。
  - **【版本 B：竹節重構版】**：在**僅限本層規則職責與命中 `span` 直接依存範圍**內，提供更具中文動感或韻律的寫法（例如 L1 將「詳細研究了」凝練為四字結構「詳加研究」或調整該動詞的受事位置；L2 將後飾子句理順為更俐落的流水短句；L3 將情境外框化為更簡練的短句切入；L4 結合斷點與四字格收束），**但同句所有非本層病灶在 A/B 兩版都必須一字不改**。
- **特殊診斷欄位處置**：
  1. **L1 `severity: "info"`**（弱動詞後接英文動作，如未加入白名單的「進行 Fine-tuning」）：於命中規則標註 `(info)`；【版本 A】可保留原語法黏著結構或僅微調前導介詞，【版本 B】依引擎 `instruction` 示範改用「做」或直上動作動詞並原樣保留英文原詞。
  2. **L4 `L4_REDUNDANT_PRONOUNS` 同指待確認**：當引擎 `instruction` 提示「先確認兩處『…』的指涉相同」時，【版本 A】保守保留可能有歧義的代詞（或僅刪無歧義的無生命「它們」），【版本 B】展示確認同指後的零形回指省略版，並於句末括號附註請作者確認兩處是否同指。
  3. **L4 `L4_CLAUSE_BREATH_OVERLOAD` 斷點處置**：當 issue 含 `suggested_breakpoint`（相對於 `target_sentence` 從 0 起算的字元索引）時，【版本 A】優先於該斷點位置補逗號分節；無 `suggested_breakpoint` 時依 `instruction` 於第二個動作或轉折處斷開，【版本 B】在不觸碰他層病灶的前提下將分句收斂至 7～15 字呼吸舒適區。

### 3. 作者最終裁決權（Author Sovereignty）

- 輸出的雙版本 Diff **僅供作者審閱與選擇**（例如作者可回覆「採用 `L14_S1` 版本 B」、「`L14_S1` 選 A，其餘選 B」或要求微調）。
- **未經作者明確確認並指示寫回之前，Agent 絕對禁止直接修改或覆寫原始文章檔案**，確保原稿 100% 零侵入。

## 本層正交隔離反例說明（L4 Orthogonality Counter-Example）

當句子同時包含 **L4 重複代詞／憋氣長句** 與 **L3 雙重因果「由於…使得…」** 及 **L1 名物化「收入的減少」／生硬被動「被徹底改變了」** 時，`zh-l4-cadence` **只能修改 L4 標記的 `span`**，絕對不可順手修改 L3 或 L1 的病灶：

- **輸入原句**（Golden Case 3）：
  > 由於他的收入的減少，使得**他的**生活方式被徹底改變了。
- **L4 掃描命中的 `span`**：第二處 `他的`（`L4_REDUNDANT_PRONOUNS`，`char_idx: 12`）
- **同句存在的他層病灶（L4 未標記，必須原字保留）**：
  - L3 `L3_CAUSAL_MALFORMED`：`由於…，使得…`（且 `使得` 在 L4 payload 中列於 `must_keep_content_words`）
  - L1 `L1_EVENT_NOMINALIZATION`：`他的收入的減少` 中的「的」
  - L1 `L1_PASSIVE_BEI`：`被徹底改變了` 中的「被」
- ❌ **錯誤改寫（違規越層：偷改了 L3 的「由於…使得…」與 L1 的「的」「被」）**：
  > ~~他因為收入減少，徹底改變了生活方式。~~
  *(違規原因：這是 `wenqi-all` 全層合修的目標句；在 `zh-l4-cadence` 單層技能中刪去「由於」「使得」「被」與名物化「的」，嚴重違反正交隔離與 `must_keep_content_words` 防呆約束。)*
- ✅ **正確改寫（嚴格正交：只處理 L4 重複領屬代詞，100% 保留 L3「由於…使得…」與 L1「收入的減少」「被徹底改變了」）**：
  - **【版本 A：微調版】**：`由於他的收入的減少，使得他的生活方式被徹底改變了。（註：請先確認兩處「他的」是否指涉同一人；若同指可採版本 B 省略後一處「他的」）`
  - **【版本 B：竹節重構版】**：`由於他的收入的減少，使得生活方式被徹底改變了。（已確認兩處「他的」同指，依話題鏈零形回指省去第二處「他的」）`

## 本層規則矩陣與引擎 `instruction` 對齊總表（L4 四大規則）

改寫方向必須與 `engine/rules/l4_cadence.py`（`#010`）輸出的 `theoretical_basis` 與 `instruction` 完全對齊：

| Rule ID | 病灶名稱 | 引擎 `theoretical_basis` | 引擎 `instruction` 核心轉換指引與語體／豁免邊界 |
| :--- | :--- | :--- | :--- |
| `L4_CLAUSE_BREATH_OVERLOAD` | 憋氣長分句（缺乏竹節斷句） | 中文竹節句以短分句推進，宜在新動作或轉折處換氣。 | 單一分句漢字數超過語體閾值（`tech` > 24 字、`essay` > 20 字、`social` > 16 字）時觸發。當 payload 含 `suggested_breakpoint` 時，引擎 `instruction` 會指明「可在『…』前分節，讓每節接近 7～15 字」；無 `suggested_breakpoint` 時，按語意於第二個動作或轉折處加逗號拆成數節，每節以 7～15 字為參考並保留原有修飾關係（不可跨層刪除 L1/L2/L3 詞彙）。 |
| `L4_REDUNDANT_PRONOUNS` | 冗餘代名詞與無生命「它們」 | 中文的話題鏈可用零形回指延續已交代的主語或領屬關係。 | 1. **無生命複數「它們」**：「話題已經清楚時可省略『它們』，需要交代指涉時保留或寫明事物名稱」（如「遂過早飛回溫暖的木舍」「河溝裏傳出焦急的叫聲」）。<br>2. **同句或連續分句重複代詞**（`他/他的/它/它的/我們/我們的`）：「先確認兩處『…』的指涉相同，省略後仍清楚時可保留前一處、省略此處」。前後分句已明確切換話題主語或使役結構必要代詞時豁免。 |
| `L4_EXISTENTIAL_COPULA_BLOAT` | 冗餘存在句與繫詞過剩 | 中文可以直接陳述問題、事件或性質，避免重疊使用存在或繫詞結構。 | 1. **存在句套疊**（`有/常有/還有 + NP + 存在/發生/出現`）：坍縮為「主語＋形容詞／數量謂語」（如「有很多問題存在」→「問題很多」）。<br>2. **基於此套語**（`基於這個/這樣/上述的原因/理由`）：簡化為「因此」或「為此」。<br>3. **是…的氾濫**（句尾非對比強調之 `是 + [很/非常/相當]? + Adj + 的。`）：剝除「是…的」，讓形容詞直接作謂語。`social` 語體預設停用 `L4_COPULA_SHI_DE` 以容許口語強調。 |
| `L4_WEAK_ENDING_VERBOSE_IDIOM` | 口水套語與段落句尾軟弱 | 雙音節與四字格能收束語氣，段尾也可用具體動詞直接落在重點。 | 1. **口水套語精簡**：依語體替換為精煉四字格或雙音節詞——「不是一句話就能說得清楚的」→「一言難盡」（`tech` 可用「難以一言蔽之／三言兩語難盡」）；「總的來說」→「總而言之／簡言之」；「在很大程度上」→「多半／主要／大幅」。<br>2. **段落末句尾軟弱**（`…是(我們)?(需要/必須/值得)(去)?(注意/思考/關注)的(一個)?(地方/問題/事情)。`）：砍掉句尾空泛的「的一個地方／的一件事情」，直接以動詞或四字短語鏗鏘收束（如「…尤須留意」「…值得深思」）。 |

## 本層 Few-Shot 案例庫（濃縮自規格 Part I §2.4.2 四類病灶）

以下案例直接節錄自規格 Part I §2.4.2 與 §5.2 L4，作為版本 A／版本 B 改寫的語感標竿：

### 1. 憋氣長分句切分為竹節流水句（`L4_CLAUSE_BREATH_OVERLOAD`）

- ❌ **病態西化**：「**基於這個原因**，我們調整了計畫。」

- ❌ **病態西化**：「這套快取機制**是非常可靠的**。」（非對比強調句，且非 `social` 語體）

### 4. 口水套語精簡與段落句尾鏗鏘收束（`L4_WEAK_ENDING_VERBOSE_IDIOM`）
